# Display

ViewBoy uses one responsive LCD canvas for the library, playlist, options, and playback status. Yoga lays out the screen; a four-shade framebuffer paints every border, selection, control, and bitmap glyph. The LCD surface fills the window edge to edge with no plastic frame. The root content is inset by a fixed eight LCD pixels on every side; this inset does not change with UI Button Pad.

The published color and spacing specification is [ViewBoy UI Design](../../../VGMManDocs/Docs/md/ViewBoy/ui-design.md).

The main screen has one full-width toolbar row containing Previous, Stop, Play/Pause, Next, Long Play, Repeat One, Playlist Random, and Library Random, in that order. All eight controls use one shared button template: equal row share, height, border, and default inset. Symbol transport labels are `<<`, `[]`, `>`, and `>>` in that order; the left chevrons sit just inside the leading border. The toolbar disappears while Options is open.

The sidebar has no section banners. Beneath its pixel-rendered search field is one row of six equal square icon buttons for Library, Path, Favorites, History, Fold/Unfold Tree, and Options. Their nine-dot artwork uses the same size and button geometry regardless of the selected text font. Library uses a stack of lines, Favorites uses a heart, Fold/Unfold Tree uses a branch diagram, and Options uses a gear. Queue, Reload, and local path opening are outside this toolbar: **View > Playback Queue** opens the active queue, **Options > Database** reloads the catalog and shows progress, and **File > Open Path…** or Command-O selects a local path. Switching between Library and Path changes only the sidebar tree mode and preserves the playlist cursor and scroll position.

The unfocused `SEARCH LIBRARY` placeholder uses the lightest visible LCD tone; active query text uses the darkest tone. Clicking the field clears and focuses it at the start, showing a blinking bitmap `|` cursor; typing filters catalog game/system names or catalog paths, and Escape clears the query or leaves search. Library groups games by system. Path lists indexed root folders and their folders/files; click a folder to expand or collapse it, double-click to load its tracks, and click a file to load its indexed tracks. The Path selection is remembered in local display preferences. The tree viewport clips and scrolls rows without resizing the sidebar or shifting the playlist pane. Wheel scrolling follows fractional LCD-dot deltas, so it can stop between rows. Bitmap `>` disclosure glyphs rotate in place as rows fold or unfold, using the shared animation timing. Child rows keep their full glyph height and slide through a clipped opening beneath their parent instead of compressing as the group folds or unfolds. Sidebar text rows are glyph-height; **Text Line Gap** alone sets the blank space between sidebar and playlist rows, independent of UI Chrome Gap. The selected sidebar row's single shaded band slides with the playlist cursor using the shared animation duration, easing, and FPS cap; it extends one LCD dot above and below the text line. Selecting a game or path loads tracks from the read-only catalog bridge. Favorites and History load their shared-store projections into ordinary playlist tabs with the same selection, close, reorder, and persistence behavior as other tabs. No pane has its own footer. The quiet app footer shows the active file path on the left and elapsed time, adjusted song duration, and playlist total on the right; Long Play and fade are included when the active backend supports Long Play.

The track pane begins with playlist tabs, followed by centered column headings. It has no separate catalog or queue title row. Selecting a game in the sidebar opens or reuses a named tab containing that game's tracks. Selecting a tab makes its list the visible playlist; while a track is playing, browsing another tab does not replace the latched playback queue. Each tab is one outlined rectangle with its left-aligned title on the left and an unframed `X` on the right; titles shrink and end in an ellipsis glyph when space is limited. Tabs use the shared auto-resize easing to slide open when added and slide shut when closed. Dragging a tab into a neighbor triggers the live swap after the pointer moves at most two LCD dots into that tab from the direction of travel; neighboring tabs ease into their new slots while the pointer is held, and changing direction retargets from their current positions. Releasing the drag eases the tab strip into the committed order, which persists in the native playlist snapshot. `[+]` duplicates the selected playlist in a new tab. One empty playlist remains available, and up to 64 playlist snapshots persist through ViewBoy's native preference store. Favorites and History are ordinary tabs sourced from the shared favorite and playback-history stores. Opening Favorites starts with no playlist rows selected; selecting a row or using the normal range-selection gestures selects tracks. Command-1 through Command-9 select the corresponding playlist tab.

The table can show the numbered `#`, favorite, file, title, game, artist, system, path, and length columns. Playlist text rows are glyph-height; **Text Line Gap** alone sets the blank space between playlist and sidebar rows. The single selection band extends one LCD dot above and below its selected text row; selected secondary rows remain shaded as part of multi-selection. Clicking in a line gap selects the closest adjacent row, with exact ties going to the preceding row. **UI Chrome Gap** controls the separation below headings and between playlist columns. UI Button Pad does not add vertical space to playlist text. The first `#` column is fixed, numbered to fit the list, and numbers each displayed row. The favorite column is labeled `FAV` and shows the shared square checkbox, outlined when off and filled when on; clicking flips it around its vertical axis and updates the shared favorite store. Right-click any table header to show or hide File, Game, Artist, Path, and Date/Time. Options exposes the same visibility controls as an unframed square-checkbox list under Library > Playlist Columns. Auto-Hide Empty Columns hides enabled metadata columns with no values in the active playlist. Every enabled column remains present in a horizontally scrollable viewport; trackpad horizontal scroll, Shift+wheel, Shift+Left/Right, and the bottom scrollbar move it. Drag header cells to reorder columns; moving the pointer at most two LCD dots into a neighbor triggers the live swap and animates surrounding headers into their slots. The easing continues during the held drag and retargets from current positions when direction changes. The numbered `#` column remains pinned. Column order is remembered in local display preferences. When Auto-size Columns is enabled, metadata widths fit their headings and available values within their column caps. Header and row widths ease together when the set changes.

Options retains its alphabetized table-of-contents pane and larger content pane. Display is the single ViewBoy page for screen profile, themes, custom colors, transport labels, playlist layout, spacing, window behavior, and motion. Library > Playlist Columns uses an unframed square-checkbox list. UI Button Pad, UI Chrome Gap, and Text Line Gap are the only adjustable spacing settings; each ranges from one to eight LCD dots, with defaults four, four, and one. UI Button Pad sets control insets and standard row height; it does not alter the fixed eight-pixel screen inset or text-row height. UI Chrome Gap sets surrounding interface spacing and playlist-column spacing. Text Line Gap controls both text panes and does not inherit chrome gaps. Spacing changes animate with the shared duration and easing, and readouts stay integer-width. Sidebar actions use equal square hit areas and centered icons, and its search field follows the shared control height, padding, and chrome gap. The quiet app footer shows the active file path on the left and a right-aligned elapsed/song/playlist clock; song and playlist durations include Long Play time and fade when Long Play applies.

The Options screen uses a vertical alphabetized table of contents and one large content pane. Opening it moves the current screen down while Options rolls in from the top; Back reverses that motion. Its pages are Audio, Database, Display, Library, Methods, Playback, and Queue. Database shows the catalog location/schema/count, reloads the catalog projection, and exposes archive-cache location, usage, enablement, size limit, clear, and Finder actions. Audio presents ten horizontal equalizer bars, each at least 100 LCD dots wide and otherwise filling the pane. Every band uses the same label width, slider width and height, value width, horizontal inset, and vertical spacing. The `[-]`/`[+]` pairs sit together before each EQ gauge and before the Volume gauge. Each EQ bar selects one of 25 gain values from flat 0 to +12 dB in 0.5 dB increments and sends changes through the native audio preference path. Its empty left endpoint is flat; +12 dB fills to the right endpoint. The four-shade fill and numeric gain animate together during increases and decreases.

The Display page combines screen profile and color theme settings. Its Micro 3×5 and Standard 5×7 bitmap fonts are independently authored and switchable. Both fonts use uppercase glyphs only; lowercase labels are normalized to uppercase before pixels are drawn. LCD dot size ranges from 2–6 device pixels per logical dot, defaulting to 3; larger dots keep the matrix more visible while reducing logical-dot count across the same window.

GameBoy, NightBoy, GrapeBoy, TealBoy, and Atomic Purple each use four framebuffer tones derived from a pixel endpoint and an LCD-background endpoint. The two middle tones are generated at one-third and two-thirds of the endpoint distance in CIELAB L*, with a* and b* interpolated along the same path. GameBoy runs from near-black pixels (`#222222`; `#080808` in High Contrast) to its lime surface. NightBoy runs from CSS `darkgrey` (`#A9A9A9`) pixels to a pure-black LCD. GrapeBoy puts charcoal pixels over rich purple (`#A64AC9`); TealBoy puts deep charcoal pixels over aqua (`#78D7D4`). Atomic Purple uses pale lavender pixels over the sampled purple shell shade (`#704883`; [reference photo](https://retrospekt.com/products/game-boy-pocket-clear-purple)). This is a screen-color approximation from an uncalibrated product image. High Contrast adjusts preset pixel endpoints and recomputes the same four tones; it does not add a fifth shade. The Custom theme uses separate BG and PIXEL fields, visible from the Display page. Inputs accept three- or six-digit hex with or without `#`, space- or comma-separated RGB channel values, CSS color names, and supported CSS color functions; the two middle tones are generated from the entered endpoints by the same equal-L* rule. Enter applies a valid value and Escape cancels. The tone preview shows the actual rendered palette. Nintendo documents the original display as a 160×144 LCD with a contrast controller; Game Boy graphics documentation defines four logical shades (white, light gray, dark gray, black) and explains that the palette register maps pixel indices to those shades. These sources establish the number and ordering, not a single RGB step curve, so equal-L* spacing is ViewBoy's consistent digital palette rule rather than a claim about measured panel voltages: [Nintendo technical data](https://www.nintendo.com/en-gb/Support/Legacy-system/Technical-data-619585.html), [Pan Docs: monochrome palettes](https://gbdev.io/pandocs/Palettes.html).

Each logical dot is a square device-pixel cell at the selected size, with a shaded face that leaves a one-device-pixel unlit LCD seam along its bottom and right edges. The grid scales with available space and device-pixel ratio, independent of the Game Boy's native 160×144 resolution. One Motion setting controls animation enablement and duration across selection, disclosure, column widths, tab reorder, EQ, spacing, scrolling, and Options. Its single draggable FPS cap control accepts any integer from 30 to 240 and defaults to 60; arrow keys adjust it by one, Shift-arrow by ten, and Home/End select the limits. The cap is shared by every animation. requestAnimationFrame timestamps pace Canvas updates; actual presentation also depends on display refresh and WKWebView compositing.

The renderer models the visible dot matrix and four quantized LCD tones, not the Game Boy's controller or electrical drive circuitry. Circuit-level simulation would not improve this app's screen output. Future authenticity work should focus on measurable optical traits such as dot aperture, cell edge, subtle viewing-angle shading, and restrained pixel response or ghosting. Keep any response effect frame-delta based and optional so static text remains crisp and canvas redraws stay inexpensive.

Click the sidebar toolbar to switch Library/Path modes, open Favorites or History, fold or unfold all groups, or open Options. The custom pixel icons are independent of the selected text font. Queue is available from **View > Playback Queue**; catalog reload is in **Options > Database**; local paths open from the native File menu or Command-O. Fold All/Unfold All stays in the toolbar and works while Search filters the tree. Click a tree row to expand or fold a Path folder or select a game/file. Right-click a game, system, Path folder, or file for **Play Now** (replace the active playlist and start its first track) or **Enqueue** (append its tracks to the active playlist). Click a playlist row to select it; clicks in the blank Text Line Gap select the nearest row. Command-click toggles rows, Shift-click selects the inclusive range, Command-A selects all, and Escape or clicking empty playlist space clears selection. Double-click a playlist row or press Enter to play the selected playlist track. If the last selected item is in the sidebar, Enter runs **Play Now** for that game, system, Path folder, or file. Click a header to sort and right-click it to open the LCD column visibility menu. Command-1 through Command-9 select playlist tabs; Command-Shift-D opens Favorites in its tab; Command-Shift-H opens Playback History in its tab; Command-comma toggles Options; Command-W closes the current playlist tab; Command-Q quits ViewBoy. Path, Console, and Disk Path views use their sidebar buttons or the View menu, Command-T duplicates a playlist in a tab. F7/F8/F9 invoke Previous/Play-Pause/Next. Arrow keys move selection (Shift extends the range), and Space toggles playback.
