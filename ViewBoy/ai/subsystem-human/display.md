# Display

ViewBoy uses one responsive LCD canvas for the library, playlist, options, and playback status. Yoga lays out the screen; a framebuffer paints every border, selection, control, and bitmap glyph. Standard color mode uses four equally stepped shades. High Contrast keeps the exact PIXEL and BG endpoints, then creates two dark-biased, per-channel RGB steps at 12% and 42% from PIXEL toward BG. The darker tones retain the configured color instead of using the standard perceptual fade. High Contrast does not tint device-cell edges or alter the grid, spacing, or configured matrix gaps. The LCD surface fills the window edge to edge with no plastic frame. The root content is inset by a fixed eight LCD pixels on every side; this inset does not change with UI Button Pad.

The published color and spacing specification is [ViewBoy UI Design](../../../VGMManDocs/Docs/md/ViewBoy/ui-design.md).

If startup lasts beyond a short reveal delay, the LCD shows a centered startup card with a pixel-letter mark, a four-step stage list, progress bar, and elapsed-time readout. It briefly confirms readiness and remains visible with the startup error if loading fails.

Opening Options while startup is in progress dismisses that overlay for the current launch. The catalog and sidebar keep loading in the background, and completion must preserve the selected Options page.

The main screen has one full-width toolbar row containing Previous, Stop, Play/Pause, Next, Long Play, Repeat One, Playlist Random, and Library Random, in that order. All eight controls use one shared button template: equal row share, height, border, and default inset. Symbol transport labels are `<<`, `[]`, `>`, and `>>` in that order; the left chevrons sit just inside the leading border. The toolbar disappears while Options is open.

The sidebar has no section banners. Beneath its pixel-rendered search field is one row of six equal square icon buttons for Library, Path, Favorites, History, Fold/Unfold Tree, and Options. Their nine-dot artwork uses the same size and button geometry regardless of the selected text font. Library uses a stack of lines, Favorites uses a heart, Fold/Unfold Tree uses a branch diagram, and Options uses a gear. Queue, Reload, and local path opening are outside this toolbar: **View > Playback Queue** opens the active queue, **Options > Database** reloads the catalog and shows progress, and **File > Open Path…** or Command-O selects a local path. Switching between Library and Path changes only the sidebar tree mode and preserves the playlist cursor and scroll position.

The unfocused `SEARCH LIBRARY` placeholder uses the lightest visible LCD tone; active query text uses the darkest tone. Clicking the field clears and focuses it at the start, showing a blinking bitmap `|` cursor; typing filters catalog game/system names or catalog paths, and Escape clears the query or leaves search. Library groups games by system. Path lists indexed root folders and their folders/files; click a folder to expand or collapse it, double-click to load its tracks, and click a file to load its indexed tracks. Root chevron ink aligns with the leading edge of the search and toolbar controls; nested disclosures indent by two glyph advances per depth. Folder and file labels align at the same depth column. The Path selection is remembered in local display preferences. The tree viewport clips and scrolls rows without resizing the sidebar or shifting the playlist pane. Wheel scrolling follows fractional LCD-dot deltas, so it can stop between rows. Bitmap `>` disclosure glyphs align with their row text and rotate in place as rows fold or unfold, using the shared animation timing. Child rows keep their full glyph height and slide through a clipped opening beneath their parent instead of compressing as the group folds or unfolds. Sidebar text rows are glyph-height; **Text Line Gap** alone sets the blank space between sidebar and playlist rows, independent of UI Chrome Gap. The selected sidebar row's single shaded band slides with the playlist cursor using the shared animation duration, easing, and FPS cap; it extends one LCD dot above and below the text line. Selecting a game or path loads tracks from the read-only catalog bridge. Favorites and History load their shared-store projections into ordinary playlist tabs with the same selection, close, reorder, and persistence behavior as other tabs. No pane has its own footer. The quiet app footer shows the active file path on the left and elapsed time, adjusted song duration, and playlist total on the right; Long Play and fade are included when the active backend supports Long Play.

The track pane begins with playlist tabs, followed by centered column headings. It has no separate catalog or queue title row. Selecting a game in the sidebar opens or reuses a named tab containing that game's tracks. Selecting a tab makes its list the visible playlist; while a track is playing, browsing another tab does not replace the latched playback queue. Each tab is one outlined rectangle with its left-aligned title on the left and an unframed `X` on the right; titles shrink and end in an ellipsis glyph when space is limited. Tabs use the shared auto-resize easing to slide open when added and slide shut when closed. Dragging a tab into a neighbor triggers the live swap after the pointer moves at most two LCD dots into that tab from the direction of travel; neighboring tabs ease into their new slots while the pointer is held, and changing direction retargets from their current positions. Releasing the drag eases the tab strip into the committed order, which persists in the native playlist snapshot. `[+]` duplicates the selected playlist in a new tab. One empty playlist remains available, and up to 64 playlist snapshots persist through ViewBoy's native preference store. Favorites and History are ordinary tabs sourced from the shared favorite and playback-history stores. Opening Favorites starts with no playlist rows selected; selecting a row or using the normal range-selection gestures selects tracks. Command-1 through Command-9 select the corresponding playlist tab.

The table can show the numbered `#`, favorite, file, title, game, artist, system, path, and length columns. Playlist text rows are glyph-height; **Text Line Gap** alone sets the blank space between playlist and sidebar rows. The single selection band extends one LCD dot above and below its selected text row; selected secondary rows remain shaded as part of multi-selection. Clicking in a line gap selects the closest adjacent row, with exact ties going to the preceding row. **UI Chrome Gap** controls the separation below headings and between playlist columns. UI Button Pad does not add vertical space to playlist text. The first `#` column is fixed, numbered to fit the list, and numbers each displayed row. The favorite column is labeled `FAV` and shows the shared square checkbox, outlined when off and filled when on; clicking flips it around its vertical axis and updates the shared favorite store. Right-click any table header to show or hide File, Game, Artist, Path, and Date/Time. Options exposes the same visibility controls as an unframed square-checkbox list under Library > Playlist Columns. Auto-Hide Empty Columns hides enabled metadata columns with no values in the active playlist. Every enabled column remains present in a horizontally scrollable viewport; trackpad horizontal scroll, Shift+wheel, and Shift+Left/Right move it without a decorative bottom scrollbar. Drag header cells to reorder columns; moving the pointer at most two LCD dots into a neighbor triggers the live swap and animates surrounding headers into their slots. The easing continues during the held drag and retargets from current positions when direction changes. The numbered `#` column remains pinned. Column order is remembered in local display preferences. When Auto-size Columns is enabled, metadata widths fit their headings and available values within their column caps. Header and row widths ease together when the set changes.

Options uses one fixed-width alphabetized navigation rail and one content area on every page. The rail is capped at 176 logical dots or 24% of the available width and does not shrink to fit page contents; a single LCD divider separates it from the content area, and neither area has a surrounding frame. The Display page places its live palette preview, custom colors, and screen profile in a left column, with interface and motion controls in a right column. Each Display section uses a full card with a shared filled title bar and enclosing outline. All Options pages share a fixed grid: 8-dot pane inset, 4-dot card inset, 4-dot gaps, and 4-dot control padding. These values do not change with the main-screen spacing preferences, keeping controls aligned and preventing spacing settings from clipping their own page. Library > Playlist Columns uses an unframed square-checkbox list. UI Button Pad, UI Chrome Gap, and Text Line Gap are the only adjustable main-screen spacing settings; each ranges from one to eight LCD dots, with defaults four, four, and one. UI Button Pad sets main-screen control insets and standard row height; it does not alter the fixed eight-pixel screen inset or text-row height. UI Chrome Gap sets main-screen interface spacing and playlist-column spacing. Text Line Gap controls both text panes and does not inherit chrome gaps. Spacing changes animate with the shared duration and easing, and readouts stay integer-width. Sidebar actions use equal square hit areas and centered icons, and its search field follows the shared control height, padding, and chrome gap. The quiet app footer shows the active file path on the left and a right-aligned elapsed/song/playlist clock; song and playlist durations include Long Play time and fade when Long Play applies.

The Options screen uses a vertical alphabetized table of contents and one large content pane. Opening it moves the current screen down while Options rolls in from the top; Back reverses that motion. Its pages are Audio, Database, Display, Library, Methods, Playback, and Queue. Database shows the catalog location/schema/count, reloads the catalog projection, and exposes archive-cache location, usage, enablement, size limit, clear, and Finder actions. Audio presents ten horizontal equalizer bars, each at least 100 LCD dots wide and otherwise filling the pane. Every band uses the same label width, slider width and height, value width, horizontal inset, and vertical spacing. The `[-]`/`[+]` pairs sit together before each EQ gauge and before the Volume gauge. Each EQ bar selects one of 25 gain values from flat 0 to +12 dB in 0.5 dB increments and sends changes through the native audio preference path. Its empty left endpoint is flat; +12 dB fills to the right endpoint. The four-shade fill and numeric gain animate together during increases and decreases.

The Display page combines screen profile and editable LCD colors. The app starts with the traditional yellow-green Game Boy palette: BG `#9BBC0F`, PIXEL `#222222`. Its Micro 3×5 and Standard 5×7 bitmap fonts are independently authored and switchable. Both fonts use uppercase glyphs only; lowercase labels are normalized to uppercase before pixels are drawn. LCD dot size ranges from 2–6 device pixels per logical dot, defaulting to 3; smaller dots give the same window a finer responsive grid. **Pixel Matrix Gaps** is off by default, so each device cell shows its exact palette color. When enabled, one device pixel at the right and bottom of each cell uses the LCD background tone. **High Contrast** retains exact BG/PIXEL endpoints and makes its intermediate tones with dark-biased, per-channel RGB steps at 12% and 42% from PIXEL toward BG. This keeps dark shades tied to the chosen pixel color instead of the standard perceptual fade. Cell edges use BG in both modes, and High Contrast leaves the device-cell mask and spacing unchanged.

BG and PIXEL are the only color controls. Inputs accept three- or six-digit hex with or without `#`, space- or comma-separated RGB channel values, CSS color names, and supported CSS color functions. ViewBoy keeps the entered text (including names such as `rebeccapurple`) and stores its resolved RGB value separately for rendering. Enter applies a valid value and Escape cancels. The tone preview shows the active four-tone palette.

This is a configurable UI palette and a visible cell-grid treatment, not a calibrated emulation of the Game Boy panel. The framebuffer grid grows or shrinks with the app window; it is not fixed at the original Game Boy's 160×144 panel resolution. Nintendo describes the classic panel as a 160×144 STN dot-matrix LCD with four shades and a contrast controller; the Color model uses a TFT panel. Standard CIELAB spacing and High Contrast's dark-biased RGB steps are digital palette rules, not measured DMG drive-voltage curves. This UI does not model reflectance, viewing-angle response, row/column crosstalk, liquid-crystal transition time, or unit-to-unit aging: [Nintendo Game Boy specifications](https://www.nintendo.com/en-gb/Hardware/Nintendo-History/Game-Boy/Game-Boy-627031.html), [Nintendo technical data](https://www.nintendo.com/en-gb/Support/Legacy-system/Technical-data-619585.html), [Pan Docs: monochrome palettes](https://gbdev.io/pandocs/Palettes.html).

Each logical dot is a square device-pixel cell at the selected size. Pixel Matrix Gaps is off by default, so every device pixel receives the exact framebuffer shade. When enabled, the right and bottom edges use the LCD surface tone in every color mode. High Contrast changes only the two intermediate palette tones; the exact PIXEL and BG endpoints, cell mask, device-pixel size, and optional gaps remain. The grid scales with available space and device-pixel ratio, independent of the Game Boy's native 160×144 resolution. One Motion setting controls animation enablement and duration across selection, disclosure, column widths, tab reorder, EQ, spacing, scrolling, and Options. Its single draggable FPS cap control accepts any integer from 30 to 240 and defaults to 60; arrow keys adjust it by one, Shift-arrow by ten, and Home/End select the limits. The cap is shared by every animation. requestAnimationFrame timestamps pace Canvas updates; actual presentation also depends on display refresh and WKWebView compositing.

The toolbar's eight controls use one shared builder and equal hit boxes. The four mode buttons use the same darker selected fill when active; their text length and current state can make them look different from the transport buttons. Previous and Next share the symbol-font glyph treatment, with `<<` intentionally aligned just inside the leading edge and `>>` centered. They still use the same button border, height, and width allocation as the other six controls.

Click the sidebar toolbar to switch Library/Path modes, open Favorites or History, fold or unfold all groups, or open Options. The custom pixel icons are independent of the selected text font. Queue is available from **View > Playback Queue**; catalog reload is in **Options > Database**; local paths open from the native File menu or Command-O. Fold All/Unfold All stays in the toolbar and works while Search filters the tree. Click a tree row to expand or fold a Path folder or select a game/file. Right-click a game, system, Path folder, or file for **Play Now** (replace the active playlist and start its first track) or **Enqueue** (append its tracks to the active playlist). Click a playlist row to select it; clicks in the blank Text Line Gap select the nearest row. Command-click toggles rows, Shift-click selects the inclusive range, Command-A selects all, and Escape or clicking empty playlist space clears selection. Double-click a playlist row or press Enter to play the selected playlist track. If the last selected item is in the sidebar, Enter runs **Play Now** for that game, system, Path folder, or file. Click a header to sort and right-click it to open the LCD column visibility menu. Command-1 through Command-9 select playlist tabs; Command-Shift-F opens Favorites in its tab; Command-Shift-H opens Playback History in its tab; Command-comma toggles Options; Command-W closes the current playlist tab; Command-Q quits ViewBoy. Path, Console, and Disk Path views use their sidebar buttons or the View menu, Command-T duplicates a playlist in a tab. F7/F8/F9 invoke Previous/Play-Pause/Next. Arrow keys move selection (Shift extends the range), and Space toggles playback.
