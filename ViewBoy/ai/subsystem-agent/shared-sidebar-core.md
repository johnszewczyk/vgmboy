# System and Game Sidebar

The LCD sidebar offers Console (Library) and Path catalog modes plus Queue, Favorites, History, Fold All/Unfold All, Reload Catalog, and Options actions. Favorites uses a bitmap heart, History a bitmap clock, and Fold All/Unfold All a three-line glyph in both LCD font profiles. These navigation buttons size to their labels so Queue and Reload remain legible. Local path opening is provided by the native File menu and Command-O rather than a duplicate sidebar button. Console mode groups the read-only catalog's games by system. Selecting a system opens or closes its game rows; child game labels align two bitmap glyph advances after the disclosure marker. Selecting a game loads its tracks into the main pane. Path mode renders `databaseFileTree` and uses `databaseFolderTracks`/`databaseFileTracks`; single-click folders fold or unfold, double-click loads a folder, and selecting a file loads that file's indexed tracks. Top-level Path folders start expanded on first use, then fold and persist like nested folders. The sidebar toolbar's Fold All / Unfold All action applies to every system group in Console mode or every expandable Path node in Path mode, including while Search filters the tree. Bulk and individual disclosures share the canonical animation timing and FPS gate. Reload refreshes the shared catalog database and re-queries its projection; the app footer displays reload progress over the active file path. Right-clicking a system, game, Path folder, or file offers Play Now and Enqueue. Play Now replaces the active tab's playlist and starts the first returned track. Enqueue adds only tracks not already in the active playlist; if that tab owns playback, the additions extend its playback queue without replacing the current track. Persist expanded Path nodes and the sidebar mode as display/native preferences respectively.

`CatalogBrowserCore` reduces individual and all-system disclosure plus game selection through the native `databaseGroupState` bridge. JavaScript keeps the returned expansion and selection state for rendering. Path-node disclosure state remains in ViewBoy's display preferences. Both group types animate from per-node progress values so nested row stacks clip away fully at completion; do not force root paths open after their saved state has been cleared. Disclosure follows the shared motion duration and FPS gate. `CatalogReader` supplies catalog games, tracks, and the indexed file tree; the UI does not scan source folders or write catalog data.

The Library pane has a fixed width derived from its navigation controls and interface gap. Keep that width as its flex basis and minimum/maximum width, with flex growth and shrink disabled. Navigation controls use natural bitmap-text widths, so full Queue and Reload labels are visible without truncation. Its tree viewport takes only the remaining vertical space (`flexBasis: 0`, `minHeight: 0`) and clips the expanding row content. Large group disclosures may animate rows, but they must not resize the pane or shift the adjacent playlist pane. Keep the search and navigation controls directly above the tree without section banners. Pane bottoms remain content areas with no status bar; the app footer owns file and playback-time readouts, temporarily replacing the file path with catalog reload progress.

Queue displays the active playback list, falling back to the browsed playlist before playback starts. Favorites reads and updates the shared `FavoriteStoreCore`. The native File menu and Command-O invoke the local path chooser and folder projection; they are separate from Path mode, which browses the catalog's indexed paths.
