# ViewBoy Integration

ViewBoy owns its AppKit host, Yoga canvas renderer, bitmap fonts, framebuffer, in-screen options, and preference namespace. AppKit hosts one WKWebView for the Yoga-laid-out Canvas screen. Keep all other screen content in the canvas; HTML and CSS provide the edge-to-edge canvas host without an outer frame.

## Data and Playback

The injected `window.viewBoy` bridge supplies read-only CatalogReader projections, shared favorite and playback-history operations, database/cache controls, frontend preferences, local-path selection, and VGMBoy transport. `window.ViewBoy.dispatch` is the macOS menu command boundary. Both names are local to ViewBoy. Long Play, Repeat One, and the `randomMode` (`off`, `playlist`, or `library`) preference are stored in `ViewBoyPreferencesSnapshot`; random shuffle history and per-cycle seen-track state stay in the renderer. Playlist Random chooses from the active queue without replacement until a cycle ends. Library Random weights catalog game groups by `trackCount`, queries only the selected game's tracks, and avoids immediately replaying the current track when another song is available. Previous and Next in either random mode use a renderer history capped at 256 track entries; Library Random history retains only each selected track rather than previously fetched game playlists. Successful native playback starts write shared `PlaybackHistoryCore` records; the History view reads these through `playbackHistoryList`.

Catalog and favorite state belongs to the native/shared cores. JavaScript owns the visible tree, current view, table layout, sorting, font and contrast preferences, and hit testing. It must not scan source paths or write the catalog. Track activation sends the native playback fields supplied by the bridge, including archive path and entry. Enter follows the most recent selection surface: it starts the selected playlist track, or runs the existing Play Now flow for the last clicked or right-clicked sidebar context (game, system, Path folder, or file). Selecting a playlist row or playlist tab returns Enter to playlist behavior.

JavaScript owns the in-memory playlist-tab projection; native `playlistTabsLoad` and `playlistTabsSave` store snapshots under a dedicated UserDefaults key. Snapshots contain up to 64 tabs, each with its title, catalog key or Path source key, track projections, primary row index, selected track IDs, range anchor, and scroll position. Saving validates the tab count, list size, and encoded payload before persistence. Loading restored snapshots must not overwrite them while the initial catalog view is being hydrated. Canvas row selection uses stable playlist IDs; the renderer paints only secondary selected rows into the base framebuffer and animates one primary selection band. Blank pixels between playlist rows hit-test to the nearest adjacent row, with exact ties resolved toward the preceding row.

## Rendering and Lifecycle

- `yoga-app.js` paints the full UI as four integer framebuffer shades and authored bitmap glyphs. Both Standard 5x7 and Micro fonts contain uppercase glyphs only; bitmap labels are normalized to uppercase before rendering. Derive four tones from each theme's font/ink and screen-surface endpoints using equal CIELAB L* intervals, with a* and b* interpolated at the same fractions. GameBoy runs dark green to lime; NightBoy runs CSS darkgray to black; PurpleBoy runs rich purple to charcoal; IdiglowBoy runs dark aqua-blue to a lighter aqua LCD. High Contrast adjusts preset ink endpoints and recomputes all four tones. Custom colors are parsed by native CSS color support and reduced to opaque sRGB endpoints before stepping. This is a consistent digital palette rule; original Game Boy references define four logical shades and an adjustable contrast control, not a universal RGB curve. Keep browser text, gradients, or selection overlays out of the screen. Playlist and catalog sidebar each have one animated primary selection band, extending exactly one logical LCD dot above and below the selected glyph-height row; never paint an additional static fill beneath the moving primary band. Secondary playlist multi-selection stays shaded in the base framebuffer. Use the shared duration, `easeSelection`, and FPS gate for both cursors. Sidebar disclosure uses the typographic `>` glyph in a uniform square and rotates its lit LCD dots in the framebuffer with the shared `easeSelection` curve.
- LCD dots are configurable from 2–6 device pixels per logical dot, defaulting to 3. The shaded face leaves a one-device-pixel unlit seam along its bottom and right edges.
- Resize events recreate canvas buffers and then render synchronously. Auto-sized table columns interpolate their widths with the shared animation duration; header cells and track cells use the same widths. When column widths are the only changing layout, animation frames update the retained Yoga nodes and repaint only the clipped catalog pane, leaving the rest of the LCD untouched; structural changes use the full renderer. Track selection paints from the cached base framebuffer without rebuilding the Yoga tree. Playlist and sidebar selection share one animation-frame loop so the cursor does not leave duplicate old/new bars during retargeting. Sidebar disclosure rotates the square `>` glyph while a clipped row stack slides by one glyph row; each text row and Text Line Gap retain their full dimensions throughout the transition. Entering Options rolls down from above; dismissing Options rolls upward, including the Command-comma toggle. Interface spacing and padding animate between their current and requested values under the shared policy. During tab or header drag, the pointer follows the dragged item and neighbors push into their new slots immediately; dropping commits tab order through the native playlist snapshot and column order through local display preferences. Every animated frame uses one shared timestamp gate with a default 60 FPS cap and a draggable integer FPS cap from 30 to 240. The gate follows requestAnimationFrame timestamps; presentation may run below the cap due to display refresh or WKWebView compositing. Page teardown cancels pending selection, sidebar, screen, spacing, equalizer, and shared column/reorder animation frames.
- The Micro and Standard glyph tables, theme, ink contrast choice, UI Button Pad, UI Chrome Gap, Text Line Gap, animation FPS, transport label style, and playlist column order are presentation preferences stored in WebKit local storage. The FPS cap is one draggable integer-range control from 30 to 240; pointer drag/click changes it, arrow keys adjust one FPS, Shift-arrow adjusts ten, and Home/End choose the endpoints. UI Button Pad controls standard text insets and control heights. UI Chrome Gap controls shared interface spacing and playlist-column spacing. One Text Line Gap controls the blank dots between both playlist and sidebar rows. Old spacing keys are read for migration, and only the unified setting names are written. Playback and playlist-column visibility preferences remain in `ViewBoyPreferencesSnapshot`.
- Playlist tab snapshots are stored through the native `playlistTabsLoad` / `playlistTabsSave` bridge, separately from display and playback preferences. Each tab retains its title, track projection, selection, and scroll position; the active tab changes the visible list and queue.
- The playlist table keeps every enabled column in one clipped horizontal viewport. Trackpad `deltaX`, Shift+wheel, the bottom scrollbar, and Shift+Left/Right scroll it; header dragging previews live push-shift movement for movable columns while `#` remains pinned first. During tab or header drags, keep the shared reorder animation running while the pointer is held. Use a two-LCD-dot pointer-entry threshold from the current direction of travel, not the neighbor midpoint. When it changes the preview order, capture currently rendered positions and retarget from those positions; do not clear the active tween on every pointer move. Drop commits and eases the layout to the saved order. Playlist and sidebar text rows are glyph-height with no vertical UI Button Pad. Text Line Gap controls both lists; UI Chrome Gap controls surrounding layout and the playlist heading-to-body and column gaps.
- Center panel titles and playlist headings. The sidebar starts with its pixel-rendered Search Library field, then six equal square bitmap actions for Library, Path, Favorites, History, Fold/Unfold Tree, and Options. Each action centers its lit icon pixels inside the same 13-dot button. Queue is available through View > Playback Queue; the local path picker stays in File > Open Path…/Command-O; catalog reload stays in Options > Database. Switching between Library and Path changes only the sidebar mode and preserves playlist selection and scroll. History projects shared `PlaybackHistoryCore` records into a newest-first playlist table and is also available through Command-Shift-H. Search filters game/system names in Console mode and indexed paths in Path mode. Path mode uses the native database file-tree projection and database-folder/file track queries; it does not enumerate source directories. The clipped tree viewport virtualizes rows and converts wheel input into fractional LCD-dot offsets, preserving sub-row movement. The playlist pane puts its single-frame, left-aligned, reorderable tab strip above the table headings; dragging a tab previews push-shift movement after the same two-LCD-dot pointer-entry threshold and commits its order through playlist snapshots. No pane adds its own status footer. A quiet app footer sits below every page: active file path on the left, elapsed time, adjusted song duration, and playlist total right aligned. Long Play time and fade apply to tracks whose backend supports Long Play.
- Options keeps a dedicated, alphabetized TOC sidebar and content pane. The active TOC button is painted with the shared selection band, inset one dot to preserve its outline, and slides between pages using the canonical duration, easing, and FPS cap; entering or leaving the Options screen remains a separate shared screen transition.
- Catalog reloads and incoming host library snapshots may update playlist data while Options is visible; they must preserve the current Options page. A host snapshot updates the Options return destination to the newly active queue, which Back then reveals.
- Right-clicking any playlist heading opens an in-canvas LCD menu for File, Game, Artist, Path, and Size. Keep visibility changes on the typed frontend-preference bridge and retain the animated square checkbox as a direct shared-favorite toggle. Auto-Hide Empty Columns is a ViewBoy-local display preference.
- `yoga-screen.css` owns only the edge-to-edge canvas host and matching surface color; it adds no bezel or membrane frame. Keep interface text and selection UI in the framebuffer. Keep `--screen-surface` synchronized with the generated theme's framebuffer surface endpoint.
- Display spacing, animation FPS, theme, and custom color endpoints in `yoga-app.js` are saved as local presentation state. Each palette has two endpoints and exactly four shades; derive the middle shades at equal CIELAB L* intervals, with no fifth shade. Custom BG/FONT input accepts short or long hex, space- or comma-separated RGB channels, and values supported by native CSS color parsing, then stores opaque sRGB endpoints. UI Button Pad changes standard text insets and control height but does not add vertical padding to sidebar or playlist text rows. UI Chrome Gap drives shared control gaps and pane spacing, including the sidebar navigation-to-tree gap, tab strip, playlist heading-to-body, and playlist column gaps. Text Line Gap alone sets the blank LCD dots between sidebar and playlist rows. The Interface page exposes one global animation enable switch, duration, and FPS cap. Duration changes are saved to both legacy native timing fields so existing typed preference storage stays compatible; all renderer animations read one canonical duration. Interpolate layout values with the shared timing and display spacing readouts as whole dots so their boxes retain stable dimensions. Clamp each spacing value to one through eight dots. The LCD canvas fills the app window edge to edge. `controlRow` and `panelTitle` provide shared row treatments; `appStatusArea` renders the app footer separately from each page's content.
- Options retains its alphabetized vertical TOC and larger content pane, each inside a thin frame. Keep the filled panel title bars, padded outlined setting groups, and aligned outlined controls; Library > Playlist Columns uses an unframed square-checkbox list. Sidebar owner sections use filled title bars labeled `OPTIONS - VIEWBOY` and `OPTIONS - VGMBoy`; checkboxes flip around the vertical axis using shared animation timing. ViewBoy pages are Database, Display, Interface, Library, and Queue; Display contains both screen-profile and theme controls. VGMBoy pages are Audio, Diagnostics, Methods, and Playback. Give the main Options row, each pane, and the page viewport explicit zero minimum width/height where they must shrink; use a zero flex basis for the main row. Clip page content to the viewport and scroll vertical overflow inside it so resizing cannot expand the dialog or push the footer off screen. Enter and exit with a top-down roll of the entire LCD frame using the shared duration, easing, and configurable frame cap. Database reads catalog location/schema/count and exposes archive-cache path, usage, enabled state, supported limit, clear, Finder, and reload operations through `databaseLocation`, `archiveCacheLocation`, `archiveCacheSummary`, `configureArchiveCache`, `clearArchiveCache`, and `reloadDatabaseLibrary`. Transport label style (`WORDS` or `SYMBOLS`) is local presentation state and must preserve accessible hit-target names. Playback owns timing and repeat/random behavior; timing values accept seconds or `MM:SS` input (Long Play additionally accepts `OPEN`) and commit on Enter/Tab. Methods owns backend tempo settings. Audio draws ten directly clickable horizontal gain bars, each with a 100-dot minimum width and a 25-value range (0 to +12 dB in 0.5 dB steps). Keep each `[-]`/`[+]` pair adjacent and before its gauge/readout. Render gain and volume as shaded gauge fills; 0 dB is the empty left endpoint and +12 dB the fully filled right endpoint. Distribute all 25 EQ tick fins evenly between shared endpoints. Keep label/value columns, slider geometry, endpoint insets, and vertical spacing identical across bands; derive click quantization from the same endpoint bounds used to paint ticks. Animate fill and numeric value on increase and decrease through the shared duration and FPS gate, and save `equalizerBandGains` through `setPreference`; audio edits call `nativePlaybackAudioConfig`.
- On the main screen, left-align transport and playback-mode toolbars in a wrapper exactly half the available screen width. Buttons in each row share the row width equally. Order transport as Previous, Stop, Play/Pause, Next; symbol labels are `<<`, `[]`, `>`, `>>`, with the left chevrons aligned to the leading edge of their button. The sidebar Library icon is a stack of lines and the Options icon is a gear. Opening the Favorites projection clears row selection so switching to that view cannot carry or seed a multi-row selection. Options has only its left-aligned Back action at the top and removes both main-screen toolbar rows.
- Shared macOS commands use Command-1 through Command-9 for playlist tabs; Command-Shift-D opens Favorites, Command-Shift-H opens Playback History, Command-comma toggles Options, and F7/F8/F9 invoke Previous/Play-Pause/Next. Path, Console, and Disk Path are selected from the sidebar or View menu. Command-W closes the active playlist tab. Command-T duplicates a playlist in a tab and Command-O opens a local path. The AppKit menu and canvas key handler must agree on the same actions.
- Playback Options persist Long Play duration, unknown-length duration, fade duration, per-backend libgme/libvgm tempo, volume, mono output, and all ten equalizer gains through `ViewBoyPreferencesSnapshot`. Resolve a track's speed support from the native playback-backend manifest instead of duplicating the format-extension table in JavaScript. Timing and speed edits reconfigure the active playback request.
- The browser canvas without the injected native bridge cannot query the catalog or control playback. Real catalog and transport checks must run in the packaged app.

## Build and Verification

`./build.sh` clean-builds and packages ViewBoy. `./launch.sh` closes the prior ViewBoy process, builds, signs, and opens the package. Validate the packaged screen and native bridge after changing the WebKit host or resource files; JavaScript syntax and Swift compilation alone do not prove live catalog or transport behavior.
