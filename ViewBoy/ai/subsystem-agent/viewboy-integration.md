# ViewBoy Integration

ViewBoy owns its AppKit host, Yoga canvas renderer, bitmap fonts, framebuffer, in-screen options, and preference namespace. AppKit hosts one WKWebView for the Yoga-laid-out Canvas screen. Keep all other screen content in the canvas; HTML and CSS provide the edge-to-edge canvas host without an outer frame.

## Data and Playback

The injected `window.viewBoy` bridge supplies read-only CatalogReader projections, shared favorite and playback-history operations, database/cache controls, frontend preferences, local-path selection, and VGMBoy transport. `window.ViewBoy.dispatch` is the macOS menu command boundary. Both names are local to ViewBoy. Long Play, Repeat One, and the `randomMode` (`off`, `playlist`, or `library`) preference are stored in `ViewBoyPreferencesSnapshot`; random shuffle history and per-cycle seen-track state stay in the renderer. Playlist Random chooses from the active queue without replacement until a cycle ends. Library Random weights catalog game groups by `trackCount`, queries only the selected game's tracks, and avoids immediately replaying the current track when another song is available. Previous and Next in either random mode use a renderer history capped at 256 track entries; Library Random history retains only each selected track rather than previously fetched game playlists. Successful native playback starts write shared `PlaybackHistoryCore` records; the Recent view reads these through `playbackHistoryList`.

Catalog and favorite state belongs to the native/shared cores. JavaScript owns the visible tree, current view, table layout, display preferences, and hit testing. `CatalogBrowserCore` supplies console groups and game/path search results; `CatalogPlaylistSorting` supplies explicit playlist order. ViewBoy maps returned game, file, and track IDs into its canvas model rather than rebuilding those policies. It must not scan source paths or write the catalog. Track activation sends the native playback fields supplied by the bridge, including archive path and entry. Enter follows the most recent selection surface: it starts the selected playlist track, or runs the existing Play Now flow for the last clicked or right-clicked sidebar context (game, system, Path folder, or file). Selecting a playlist row or playlist tab returns Enter to playlist behavior.

JavaScript owns the in-memory playlist-tab payload; native `playlistTabsLoad` and `playlistTabsSave` store snapshots under a dedicated UserDefaults key. `PlaylistTabsPersistenceCore` reduces ordinary activate, insert, close, move, and restore actions so ViewBoy follows the same order and active-tab fallback as CocoaSpice and SB2. Snapshots contain up to 64 tabs, each with its title, catalog key or Path source key, track projections, primary row index, selected track IDs, range anchor, and scroll position. Saving validates the tab count, list size, and encoded payload before persistence. Loading restored snapshots must not overwrite them while the initial catalog view is being hydrated. Canvas row selection uses stable playlist IDs; the renderer paints only secondary selected rows into the base framebuffer and animates one primary selection band. Blank pixels between playlist rows hit-test to the nearest adjacent row, with exact ties resolved toward the preceding row.

## Rendering and Lifecycle

- `yoga-app.js` paints the full UI into an integer framebuffer with authored bitmap glyphs. Standard 5x7 and Micro fonts contain uppercase glyphs only; normalize labels before rasterizing. The default endpoints are Game Boy yellow-green `#9BBC0F` BG and black `#000000` PIXEL. Preserve exact entered CSS text separately from its resolved sRGB value. RENDERING selects LCD linear-light reflectance mixing or DIRECT interpolation in sRGB channels. Both preserve exact color endpoints at zero boost and retain intermediate muted/header tones. PALETTE independently selects COLOR, 8 GRAY or 16 GRAY; grayscale palettes retain their TEXT SHADE and BG SHADE controls. Matrix geometry and Contrast Boost remain independent. Save `renderingMode` and `paletteMode` independently; migrate the legacy combined `pixelShadeMode` only on read. Keep text at selected ink and derive muted and selection tones in the direction of the substrate, including inverse polarity. Shading modes change color mapping only; preserve framebuffer geometry, device-cell mask, matrix gaps, and spacing. Keep interface text and selection UI in the framebuffer. Playlist and catalog sidebar each have one animated primary selection band, extending exactly one LCD dot above and below its glyph-height row; never paint a second static fill beneath it. Secondary playlist multi-selection uses an outline. Use shared duration, easing, and FPS gate for both cursors. Sidebar disclosure uses the typographic `>` glyph in a uniform square and rotates its lit dots in the framebuffer.
- LCD dots are configurable from 2–6 device pixels per logical dot, defaulting to 3. New installations enable Pixel Matrix Gaps using the fractional STN aperture; explicit saved off choices remain off. The optional Classic profile uses one right/bottom device-pixel gutter. Keep device-cell coverage independent of color and output gain. Dot snapshots and canvas presentation use the same cached cells. Follow [LCD rendering](lcd-rendering.md) for aperture and contrast invariants.
- Resize events recreate canvas buffers and then render synchronously. Auto-sized table columns interpolate their widths with the shared animation duration; header cells and track cells use the same widths. When column widths are the only changing layout, animation frames update the retained Yoga nodes and repaint only the clipped catalog pane, leaving the rest of the LCD untouched; structural changes use the full renderer. Track selection paints from the cached base framebuffer without rebuilding the Yoga tree. Playlist and sidebar selection share one animation-frame loop so the cursor does not leave duplicate old/new bars during retargeting. Sidebar disclosure rotates the square `>` glyph while a clipped row stack slides by one glyph row; each text row and Text Line Gap retain their full dimensions throughout the transition. Entering Options rolls down from above; dismissing Options rolls upward, including the Command-comma toggle. Interface spacing and padding animate between their current and requested values under the shared policy. During tab or header drag, the pointer follows the dragged item and neighbors push into their new slots immediately; dropping commits tab order through the native playlist snapshot and column order through local display preferences. All interpolations use `motion.js` to evaluate SB2's cubic-bezier(0.2, 0, 0, 1), solving the time coordinate before the position coordinate. Retargeting begins at the current interpolated position; disabled animations and zero duration still settle immediately. Every animated frame uses one shared timestamp gate with a default 60 FPS cap and a draggable integer FPS cap from 30 to 240. The gate follows requestAnimationFrame timestamps; presentation may run below the cap due to display refresh or WKWebView compositing. Page teardown cancels pending selection, sidebar, screen, spacing, equalizer, and shared column/reorder animation frames.
- The Micro and Standard glyph tables, custom BG/PIXEL endpoints, UI Button Pad, UI Chrome Gap, Text Line Gap, animation FPS, transport label style, and playlist column order are presentation preferences stored in WebKit local storage. The FPS cap is one draggable integer-range control from 30 to 240; pointer drag/click changes it, arrow keys adjust one FPS, Shift-arrow adjusts ten, and Home/End choose the endpoints. UI Button Pad controls standard text insets and control heights. UI Chrome Gap controls shared interface spacing and playlist-column spacing. One Text Line Gap controls the blank dots between both playlist and sidebar rows. Old spacing keys are read for migration, and only the unified setting names are written. Playback and playlist-column visibility preferences remain in `ViewBoyPreferencesSnapshot`.
- Playlist tab snapshots are stored through the native `playlistTabsLoad` / `playlistTabsSave` bridge, separately from display and playback preferences. Each tab retains its title, track projection, selection, and scroll position; the active tab changes the visible list and queue.
- The playlist table keeps every enabled column in one clipped horizontal viewport. Trackpad `deltaX`, Shift+wheel, and Shift+Left/Right scroll it; there is no always-visible bottom scrollbar or track rule. Header dragging previews live push-shift movement for movable columns while `#` remains pinned first. During tab or header drags, keep the shared reorder animation running while the pointer is held. Use a two-LCD-dot pointer-entry threshold from the current direction of travel, not the neighbor midpoint. When it changes the preview order, capture currently rendered positions and retarget from those positions; do not clear the active tween on every pointer move. Drop commits and eases the layout to the saved order. Playlist and library sidebar text rows are glyph-height with no vertical UI Button Pad. Text Line Gap controls both lists; UI Chrome Gap controls surrounding layout and the playlist heading-to-body and column gaps.
- Center panel titles and playlist headings. The sidebar starts with its pixel-rendered Search Library field, then six equal square bitmap actions for Library, Path, Favorites, Recent, Fold/Unfold Tree, and Options. Each action centers its lit icon pixels inside the same 13-dot button. Queue is available through View > Playback Queue; the local path picker stays in File > Open Path…/Command-O; catalog reload stays in Options > Database. Switching between Library and Path changes only the sidebar mode and preserves playlist selection and scroll. Recent projects shared `PlaybackHistoryCore` records into a newest-first playlist table and is also available through Command-Shift-H. Search filters game/system names in Console mode and indexed paths in Path mode. Path mode uses the native database file-tree projection and database-folder/file track queries; it does not enumerate source directories. The clipped tree viewport virtualizes rows and converts wheel input into fractional LCD-dot offsets, preserving sub-row movement. The playlist pane puts its single-frame, left-aligned, reorderable tab strip above the table headings; dragging a tab previews push-shift movement after the same two-LCD-dot pointer-entry threshold and commits its order through playlist snapshots. No pane adds its own status footer. A quiet app footer sits below every page: active file path on the left, elapsed time, adjusted song duration, and playlist total right aligned. Long Play time and fade apply to tracks whose backend supports Long Play.
- Options reuses the home shell: retain the single-line transport toolbar, sidebar pane, and playback footer while replacing the playlist pane with the selected settings page. Keep the sidebar action row and replace library rows with grouped ViewBoy and VGMBoy page links. Selecting a page or changing a control must preserve Options; the gear, Escape, or Command-comma exits through the roll transition. The selected page uses the shared animated selection band; Options links add four logical dots around glyph-height text so the shaded marker has breathing room around the glyphs; redraw group headings when the marker crosses them. Preserve the Display page responsive card layout and scroll overflow inside the content pane.
- Catalog reloads, delayed Path queries, and Favorites/Recent results may update data while Options is visible; preserve the selected page and keep the Options shell open. Main-sidebar actions return to their requested view through the roll transition.
- Right-clicking any playlist heading opens an in-canvas LCD menu for File, Game, Artist, Path, and Date/Time. Keep visibility changes on the typed frontend-preference bridge and retain the animated square checkbox as a direct shared-favorite toggle. Auto-Hide Empty Columns is a ViewBoy-local display preference.
- `yoga-screen.css` owns only the edge-to-edge canvas host and matching surface color; it adds no bezel. Keep interface text and selection UI in the framebuffer. The framebuffer paints the selected BG tone to every edge; `buildTree()` keeps root content inset by a fixed eight LCD pixels, independent of UI Button Pad. Keep `--screen-surface` synchronized with the rendered BG. Options panes, cards, gaps and controls share the saved layout spacing values. Navigation and content headers use the same filled `panelTitle` template and align at their top edge. Pane padding is in logical dots, converted once to Yoga units. Use 1× UI Gap for insets and control gaps, and the shared `uiSectionGap()` (2× UI Gap) for card/column gaps and below pane/card headers. Palette preview is one labeled PREVIEW strip, bounded and aligned with the color fields, with contiguous tone segments and all 8/16 grayscale tones. Pane/card headings and field labels align left. Selectors, color fields and numeric groups start at the same one-third field column. Numeric groups keep square minus/plus controls beside a fixed-width, left-aligned readout; narrow rows stack the label above controls. Button captions stay centered within their hit boxes. Card minimum heights count the header margin once.
- Display spacing, animation FPS, and custom color endpoints in `yoga-app.js` are saved as local presentation state. New installations use BG `#9BBC0F`, PIXEL `#000000`, and four-tone LCD output; the four semantic framebuffer shades map to selected text/background endpoints plus intermediate ink and highlight tones. Preserve grid, spacing, and matrix enablement across shading modes; the LCD model owns the selected aperture profile. Custom BG/PIXEL input accepts short/long hex, space- or comma-separated RGB channels, and CSS color names/functions; store resolved sRGB separately from exact field text. UI Button Pad changes control text insets and height in both main and Options views but not text-row height. UI Chrome Gap drives control/pane/card spacing; Text Line Gap sets blank dots between library/playlist rows and Options links. Reset Spacing applies all three defaults in one persisted update and one retargeted animation. Display exposes pixel method and tone selection, transport labels, layout spacing, window, and shared Motion settings. Duration remains compatible with both native timing fields; all renderer animations read one canonical duration. Clamp spacing to one through eight dots and retain integer readouts. The LCD canvas fills the app window; `controlRow`, `panelTitle`, and `appStatusArea` provide shared UI treatments.
- Late playlist-tab restoration may update the active playlist while Options is open, but must preserve the visible Options screen; initial restoration selects Library only when the user has not opened Options. Opening Options during startup dismisses the startup overlay for that launch while catalog and playlist restoration continue in the background.
- The main shell stays visible in Options: one eight-button toolbar, one sidebar pane, one content pane, and one playback footer. Sidebar rows become grouped links to ViewBoy pages (Database, Display, Library, Queue) and VGMBoy pages (Audio, Diagnostics, Methods, Playback). Display contains pixel method, shade selection, custom colors, screen profile, transport, layout, window, and motion controls. Its full cards use a shared filled title bar and outline; Library > Playlist Columns uses square-checkbox rows. Keep options content clipped to its pane and scroll internally so the footer remains visible. The selected page uses the common selection-band animation. Page/control interaction preserves Options; the sidebar gear, Escape, or Command-comma exits with the screen roll. Use the shared top-down roll with the shared duration, easing, and FPS cap. Database retains catalog/cache operations. Transport style remains local presentation state with accessible names; timing, tempo, and VGMBoy audio keep their current frontend/native ownership.
- The shared shell keeps one full-width, single-line toolbar of eight equal-width actions ordered Previous, Stop, Play/Pause, Next, Long Play, Repeat One, Playlist Random, Library Random, both at home and in Options. Route every action through the same button template with equal height and border. Symbol transport uses centered mirrored bitmap double chevrons for Previous/Next and `[]` / `>` for Stop/Play. Tab close uses a seven-dot square-framed bitmap X in a square reserved target; tab minimum width must contain it even when the title collapses. Anchor the close cell to the final rasterized parent bounds in both collection and painting; Yoga child offsets can otherwise exceed the floored parent edge by one dot. The sidebar Library icon is a stack of lines and the Options icon is a gear. Opening Favorites clears row selection.
- Shared macOS commands use Command-1 through Command-9 for playlist tabs; Command-Shift-F opens Favorites, Command-Shift-H opens Recent, Command-comma toggles Options, and F7/F8/F9 invoke Previous/Play-Pause/Next. Path, Console, and Disk Path are selected from the sidebar or View menu. Command-W closes the active playlist tab. Command-T duplicates a playlist in a tab and Command-O opens a local path. The AppKit menu and canvas key handler must agree on the same actions.
- Playback Options persist Long Play duration, unknown-length duration, fade duration, per-backend libgme/libvgm tempo, volume, mono output, and all ten equalizer gains through `ViewBoyPreferencesSnapshot`. Resolve a track's speed support from the native playback-backend manifest instead of duplicating the format-extension table in JavaScript. Timing and speed edits reconfigure the active playback request.
- The browser canvas without the injected native bridge cannot query the catalog or control playback. Real catalog and transport checks must run in the packaged app.

## Build and Verification

`./build.sh` clean-builds and packages ViewBoy. `./launch.sh` closes the prior ViewBoy process, builds, signs, and opens the package. Validate the packaged screen and native bridge after changing the WebKit host or resource files; JavaScript syntax and Swift compilation alone do not prove live catalog or transport behavior.

## Options Control Geometry

Numeric rows reserve one value-column width and square minus/plus buttons.
Contrast, FPS and Volume place the common gauge on a separate full-width row.
EQ retains inline gauges in wider panes and stacks a full-width gauge below
its control row when the available content is under 230 logical dots. All ten
bands use identical columns. Gauge bounds use the complete integer-pixel span;
ticks round normalized positions rather than shortening the track to an exact
multiple of the step count. Fill width includes both endpoints, so maximum
fills the last track pixel. Clear the complete interior before every update.
Audio pointer gestures preview locally, commit preferences and audio configuration
on release, and restore the starting value on cancellation. Keyboard changes
commit immediately. Focused range keys apply only on their owning Options page.

Gauge fill spans the one-dot-border interior. Tick positions include the outer left/right borders as endpoints; paint only internal notches. Omit the moving thumb at zero and maximum so endpoints have no holes. All numeric field groups share the leading selector column; stack labels when the label or controls cannot fit.
