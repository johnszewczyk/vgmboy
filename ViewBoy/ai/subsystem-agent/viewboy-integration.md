# ViewBoy Integration

ViewBoy owns its AppKit host, Yoga canvas renderer, bitmap fonts, framebuffer, in-screen options, and preference namespace. AppKit hosts one WKWebView for the Yoga-laid-out Canvas screen. Keep all other screen content in the canvas; HTML and CSS provide the canvas host and three flat membrane outlines.

## Data and Playback

The injected `window.viewBoy` bridge supplies read-only CatalogReader projections, shared favorite and playback-history operations, database/cache controls, frontend preferences, local-path selection, and VGMBoy transport. `window.ViewBoy.dispatch` is the macOS menu command boundary. Both names are local to ViewBoy. Long Play, Repeat One, and the `randomMode` (`off`, `playlist`, or `library`) preference are stored in `ViewBoyPreferencesSnapshot`; random shuffle history and per-cycle seen-track state stay in the renderer. Playlist Random chooses from the active queue without replacement until a cycle ends. Library Random weights catalog game groups by `trackCount`, queries only the selected game's tracks, and avoids immediately replaying the current track when another song is available. Previous and Next in either random mode use a renderer history capped at 256 track entries; Library Random history retains only each selected track rather than previously fetched game playlists. Successful native playback starts write shared `PlaybackHistoryCore` records; the History view reads these through `playbackHistoryList`.

Catalog and favorite state belongs to the native/shared cores. JavaScript owns the visible tree, current view, table layout, sorting, font and contrast preferences, and hit testing. It must not scan source paths or write the catalog. Track activation sends the native playback fields supplied by the bridge, including archive path and entry.

JavaScript owns the in-memory playlist-tab projection; native `playlistTabsLoad` and `playlistTabsSave` store snapshots under a dedicated UserDefaults key. Snapshots contain up to 64 tabs, each with its title, catalog key or Path source key, track projections, selection, and scroll position. Saving validates the tab count, list size, and encoded payload before persistence. Loading restored snapshots must not overwrite them while the initial catalog view is being hydrated.

## Rendering and Lifecycle

- `yoga-app.js` paints the full UI as four integer framebuffer shades and authored bitmap glyphs. Both Standard 5x7 and Micro fonts contain uppercase glyphs only; bitmap labels are normalized to uppercase before rendering. GameBoy and NightBoy are palettes for the same framebuffer; High Contrast changes shade 0 only. Keep browser text, gradients, or selection overlays out of the screen. Sidebar disclosure uses the typographic `>` glyph in a uniform square and rotates its lit LCD dots in the framebuffer with the shared `easeSelection` curve.
- LCD dots are configurable from 2–6 device pixels per logical dot, defaulting to 3. The shaded face leaves a one-device-pixel unlit seam along its bottom and right edges.
- Resize events recreate canvas buffers and then render synchronously. Auto-sized table columns interpolate their widths with the shared animation duration; header cells and track cells use the same widths. Track selection paints from the cached base framebuffer without rebuilding the Yoga tree. Sidebar disclosure rotates the square `>` glyph while a clipped row stack slides by one glyph row; each text row and Text Line Gap retain their full dimensions throughout the transition. Entering Options rolls down from above; dismissing Options rolls upward, including the Command-comma toggle. Interface spacing and padding animate between their current and requested values under the shared policy. During tab or header drag, the pointer follows the dragged item and neighbors push into their new slots immediately; dropping commits tab order through the native playlist snapshot and column order through local display preferences. Every animated frame uses one shared timestamp gate with a default 60 FPS cap and selectable 30, 60, 90, 120, or 144 FPS caps. The gate follows requestAnimationFrame timestamps; presentation may run below the cap due to display refresh or WKWebView compositing. Page teardown cancels pending selection, sidebar, screen, spacing, equalizer, and shared column/reorder animation frames.
- The Micro and Standard glyph tables, theme, ink contrast choice, UI Button Pad, UI Chrome Gap, Text Line Gap, animation FPS, transport label style, and playlist column order are presentation preferences stored in WebKit local storage. UI Button Pad controls standard text insets and control heights. UI Chrome Gap controls shared interface spacing and playlist-column spacing. One Text Line Gap controls the blank dots between both playlist and sidebar rows. Old spacing keys are read for migration, and only the unified setting names are written. Playback and playlist-column visibility preferences remain in `ViewBoyPreferencesSnapshot`.
- Playlist tab snapshots are stored through the native `playlistTabsLoad` / `playlistTabsSave` bridge, separately from display and playback preferences. Each tab retains its title, track projection, selection, and scroll position; the active tab changes the visible list and queue.
- The playlist table keeps every enabled column in one clipped horizontal viewport. Trackpad `deltaX`, Shift+wheel, the bottom scrollbar, and Shift+Left/Right scroll it; header dragging previews live push-shift movement for movable columns while `#` remains pinned first. Playlist and sidebar text rows are glyph-height with no vertical UI Button Pad. Text Line Gap controls both lists; UI Chrome Gap controls surrounding layout and the playlist heading-to-body and column gaps.
- Center panel titles and playlist headings. The sidebar starts with its pixel-rendered Search Library field, then compact Library, Path, Queue, Favorites, History, Open Path, Sync, and Options actions and the catalog tree. History projects shared `PlaybackHistoryCore` records into a newest-first playlist table and is also available through Command-Shift-H. Search filters game/system names in Console mode and indexed paths in Path mode. Path mode uses the native database file-tree projection and database-folder/file track queries; it does not enumerate source directories. The clipped tree viewport virtualizes rows and converts wheel input into fractional LCD-dot offsets, preserving sub-row movement. The playlist pane puts its single-frame, left-aligned, reorderable tab strip above the table headings; dragging a tab previews push-shift movement and commits its order through playlist snapshots. No pane adds its own status footer. One app-wide one-row file-location readout sits below every page and shows the active playback file or selected file, including the archive member when available.
- Right-clicking any playlist heading opens an in-canvas LCD menu for File, Game, Artist, Path, and Size. Keep visibility changes on the typed frontend-preference bridge and retain `[x]`/`[]` as a direct shared-favorite toggle.
- `yoga-screen.css` owns only the narrow shell around the canvas. Its `data-theme="NIGHTBOY"` palette uses a dark-purple shell and silver bevels; keep interface text and selection UI in the framebuffer.
- Display spacing and animation FPS in `yoga-app.js` are saved as local presentation state. UI Button Pad changes standard text insets and control height but does not add vertical padding to sidebar or playlist text rows. UI Chrome Gap drives shared control gaps and pane spacing, including the sidebar navigation-to-tree gap, tab strip, playlist heading-to-body, and playlist column gaps. Text Line Gap alone sets the blank LCD dots between sidebar and playlist rows. The Interface page exposes one global animation enable switch, duration, and FPS cap. Duration changes are saved to both legacy native timing fields so existing typed preference storage stays compatible; all renderer animations read one canonical duration. Interpolate layout values with the shared timing and display spacing readouts as whole dots so their boxes retain stable dimensions. Clamp each spacing value to one through eight dots. The app border remains eight dots. `controlRow`, `panelTitle`, and `appStatusArea` provide shared row treatments; the file-location readout remains separate from every page's content.
- Options retains its alphabetized vertical TOC and larger content pane. Keep the existing page controls and grouped settings; Library > Playlist Columns is the simple unframed `[x]` / `[ ]` checklist. Its pages are Audio, Database, Display, Interface, Library, Methods, Playback, Theme, and Transport. Enter and exit with a top-down roll of the entire LCD frame using the shared duration, easing, and configurable frame cap. Database reads catalog location/schema/count and exposes archive-cache path, usage, enabled state, supported limit, clear, Finder, and reload operations through `databaseLocation`, `archiveCacheLocation`, `archiveCacheSummary`, `configureArchiveCache`, `clearArchiveCache`, and `reloadDatabaseLibrary`. Transport label style (`WORDS` or `SYMBOLS`) is local presentation state and must preserve accessible hit-target names. Playback owns timing and repeat/random behavior; timing values accept seconds or `MM:SS` input (Long Play additionally accepts `OPEN`) and commit on Enter/Tab. Methods owns backend tempo settings. Audio draws ten directly clickable horizontal gain bars, each with a 100-dot minimum width and a 25-value range (0 to +12 dB in 0.5 dB steps). Keep each `[-]`/`[+]` pair adjacent and before its gauge/readout. Render gain and volume as shaded gauge fills; 0 dB is the empty left endpoint and +12 dB the fully filled right endpoint. Distribute all 25 EQ tick fins evenly between shared endpoints. Keep label/value columns, slider geometry, endpoint insets, and vertical spacing identical across bands; derive click quantization from the same endpoint bounds used to paint ticks. Animate fill and numeric value on increase and decrease through the shared duration and FPS gate, and save `equalizerBandGains` through `setPreference`; audio edits call `nativePlaybackAudioConfig`.
- On the main screen, center transport and playback-mode toolbars inside a wrapper exactly half the available screen width. Buttons in each row share the row width equally; keep Options in the sidebar action row. Options has only its Back action at the top and removes both main-screen toolbar rows.
- Shared macOS commands use Command-1 through Command-9 for playlist tabs; Command-Shift-D opens Favorites, Command-Shift-H opens Playback History, Command-comma toggles Options, and F7/F8/F9 invoke Previous/Play-Pause/Next. Path, Console, and Disk Path are selected from the sidebar or View menu. Command-W closes the active playlist tab. Command-T duplicates a playlist in a tab and Command-O opens a local path. The AppKit menu and canvas key handler must agree on the same actions.
- Playback Options persist Long Play duration, unknown-length duration, fade duration, per-backend libgme/libvgm tempo, volume, mono output, and all ten equalizer gains through `ViewBoyPreferencesSnapshot`. Resolve a track's speed support from the native playback-backend manifest instead of duplicating the format-extension table in JavaScript. Timing and speed edits reconfigure the active playback request.
- The browser canvas without the injected native bridge cannot query the catalog or control playback. Real catalog and transport checks must run in the packaged app.

## Build and Verification

`./build.sh` clean-builds and packages ViewBoy. `./launch.sh` closes the prior ViewBoy process, builds, signs, and opens the package. Validate the packaged screen and native bridge after changing the WebKit host or resource files; JavaScript syntax and Swift compilation alone do not prove live catalog or transport behavior.
